# 精简Modbus接口

只保留三个函数，不再提供通用寄存器库、回调框架或命令队列。

## 1. 读取EMF89瞬时流量

```c
float flow;
if (Modbus_ReadFlow(1U, &flow) == HAL_OK)
{
    /* flow为有效新测量，单位以仪表设置为准。 */
}
```

参数1是仪表实际地址，不一定为1。函数使用UART5，固定查询03/0252/两个寄存器，
包含PD4方向控制、发送、接收、CRC校验和IEEE754浮点转换。
失败时不修改flow；调用者必须检查返回值，不能将旧值当作新采样。
仅主循环阻塞调用，不同时使用UART5接收中断/DMA，不并发查询。

UART5当前仍为115200、8N1；EMF89手册列出1200~38400，需改成与仪表一致。
PD4高发送、低接收，需与实际DE/RE电路一致。手册示例负流量-12.5可正常返回。
函数在事务间保守等待静默，适用于独占的流量计总线。
每个发送/接收阶段最长200ms；异常响应和其他协议错误统一返回HAL_ERROR。
此精简版不实现逐字节RTU间隔检测，也不主动修改波特率或自动轮询。

## 2. 解析上位机命令

```c
ModbusCommand command;
if (Modbus_ParseCommand(frame, frame_length, &command))
{
    /* 按command.address和command.value检查并处理命令。 */
}
```

只支持06写单个寄存器，请求固定8字节。控制板地址由modbus.h中的
MODBUS_HOST_ADDRESS定义；地址0广播也可以解析。
上位机串口尚未确定，其收发代码需要先完成RTU分帧，再在主循环调用此函数。
本函数不收UART字节、不执行阀门动作；未指定地址和数值的业务含义。

## 3. 构建上位机应答

```c
uint8_t response[8];
/* 必须先检查并处理command。下面exception由实际处理结果决定。 */
uint16_t length = Modbus_BuildReply(&command, exception, response);
if (length != 0U)
{
    /* 用实际的上位机串口发送response；不要发往流量计UART5。 */
}
```

exception=0表示成功，02地址错误、03数值错误、04执行失败。
成功应答8字节，异常应答5字节；广播返回0且不能回复。
只对成功解析的命令调用，response至少8字节。未接受/执行时不能回复成功。
不支持其他功能码；如果后续需要上位机读状态，再按实际需求增加。

## 验证

Debug构建通过；主机模拟测试通过手册请求帧、-12.5浮点解析、CRC错误、
非有限值、异常响应、收发超时、方向恢复、06解析及广播不响应。
未进行真实流量计/上位机硬件联调。main.c原有DAC与气缸启动行为未改动。
